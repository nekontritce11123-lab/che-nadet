## Что покрыто проверками ядра

Отдельные группы проверяют нормальные и крайние температуры, профиль чувствительности и активности, ветер/порывы, влажность, дождь/интенсивность/вероятность, снег, UV, ночь, грозу, ледяные осадки, холод/жару, сочетания защиты и слоёв, причины решений, неполные и некорректные поля.

Матрица включает **264 комбинации** параметров и проход по **1100 температурным шагам** для свойства монотонности/плавности. 4196 assertions — не 4196 различных погодных сценариев. Подробный список именованных групп: [CORE_CHECKS.md](CORE_CHECKS.md).

Данные проверяются на корректность единиц и временных интервалов, разделение температуры и ощущений, время UTC/часовой пояс, нормализацию накопленных осадков, укороченные/null-массивы API, соответствие города кэшу, возраст ответа, порядок запоздавших запросов и конечное время вероятности дождя.

Регрессии сначала воспроизводились неуспешными тестами, затем исправлялись:
- Сохранённый прогноз не должен отсчитывать «ближайшие часы» от старой загрузки.
- Противоречивый feels-like не должен давать летнюю одежду при экстремальном фактическом морозе или зимний комплект при экстремальной жаре.
- Насыщенная влажность за пределами fallback-formula domain не должна скрывать предупреждение о влажной жаре.
- Вероятность дождя из прошедшего часа не должна трактоваться как предстоящая.

Fixtures искусственные. Это **не успешный live-запрос в Open-Meteo** и не доказательство физиологической точности одежды.

## Саморевью и принятые решения

Выполнено **саморевью автора, не независимый code review**: границы API/ядра, единицы, временная семантика, безопасность профиля, отсечение старых ответов, разрешения, отсутствие постоянной геолокации, backup/privacy, native entry points и полнота документации. Нативная часть остаётся неподтверждённой до сборки.

Решения при ограничениях среды: продолжить разработку локально вместо остановки на плане; не подменять push локальным коммитом; держать Android-кандидат отдельно от проверенного main; предоставить source-only checksum bootstrap вместо недоступного Wrapper JAR; явно отделить тесты ядра от нативной проверки. Цена этих решений — переносимость bootstrap и Android-интеграция ещё нуждаются в проверке, а публичная поставка отсутствует.

Не расширялись вне v1: pull-to-refresh вместо кнопки, офлайн-каталог городов, отдельная развитая модель тумана/мокрого снега, гардероб при обычном потеплении, физиологическая калибровка. HTTP имеет ограничение размера и operation timeouts, но не строгий общий deadline.
