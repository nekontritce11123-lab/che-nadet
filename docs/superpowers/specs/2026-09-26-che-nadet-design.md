# «Чё надеть?» — дизайн v1

Продукт: Android-приложение на русском языке. За несколько секунд показывает условия, ощущение и послойный совет. Без аккаунта, рекламы, AI и фонового слежения. Пользователь поручил автономно принимать обратимые решения и выполнять этапы без дополнительных согласований.

## Решения

- Нативный Kotlin + Compose / Material 3: одна платформа, один экран, системная доступность. Flutter/React Native не дают преимущества для этого небольшого Android-only проекта.
- `:core`: обычный Kotlin/JVM, доменные модели, детерминированный движок, объяснения, политики свежести и прогноза. Никаких Android/API зависимостей.
- `:app`: UI → ViewModel / StateFlow → репозиторий; HTTPS, Open-Meteo mapper, foreground LocationManager, DataStore. Простое ручное внедрение зависимостей вместо DI-фреймворка.
- Версии фиксируются, а не обозначаются «latest». AGP 8.13.2 + Gradle 8.13 + Kotlin 2.3.21, API 36, min API 26. Консервативный поддерживаемый стек без миграции на новый DSL AGP 9.
- Open-Meteo: нет секретного ключа; текущие модельные условия и почасовой прогноз. Бесплатный endpoint только для некоммерческого приложения. Атрибуция Open-Meteo / GeoNames / CC BY 4.0 обязательна.
- Главный экран: город → температура / ощущается → одежда → взять с собой → причины → погодные детали. Крупная типографика, адаптивные переносы, минимум декоративных элементов. Светлая/тёмная тема.

## Движок

Вход `WeatherConditions + UserProfile`, выход `Recommendation` с перечислениями предметов, причин и предупреждений. Человекочитаемые тексты — отдельный слой. Apparent temperature не корректируется повторно ветром и влажностью. При отсутствии — ограниченный по области применимости wind chill / heat index либо фактическая температура с объяснением неопределённости. Персонализация меняет только одежду, не показание «ощущается».

Непрерывная потребность в утеплении, небольшие ступени съёмных слоёв и пограничные зоны. Ветер и мокрота влияют на защитную оболочку/обувь независимо от утепления. Опасности имеют приоритет. Зонт исключается при сильном/неизвестном ветре; при грозе приоритет укрытию. Низкая облачность не заменяет UV. При ночной погоде не заявлять текущую солнечность. Прогноз рассматривается только внутри выбранного горизонта активности.

Численные пороги одежды, поправки профиля и пороги предупреждений — прозрачные продуктовые эвристики, а не медицинский стандарт или официальное предупреждение. Не утверждать, что влажность сама по себе существенно охлаждает зимой. Не обещать точность ощущения или защиту от экстремальной погоды.

## Данные и ошибки

Запрашивать только используемые параметры. Unix time, timezone города только для отображения. Вероятность дождя не равна интенсивности. Текущие осадки делить на длительность current.interval для эквивалентной часовой интенсивности. Отсутствующее значение не превращать в ноль.

Местоположение — только приблизительное и только при активном экране, с таймаутом. Отказ не блокирует ручной поиск. Геокодер необязателен: честное название «Моё местоположение» лучше неверного города. Смена города отменяет старый запрос. Кэш привязан к координатам; ни одного совета от предыдущего города.

Кэш старше 30 минут или модельные условия старше 90 минут помечаются как сохранённые. После 6 часов рекомендации не выдаются; после 24 часов не показываются и старые цифры. Время из будущего не считать свежим. Настройки, последний выбор и ограниченный кэш приватны, Android backup выключен. Координаты уходят погодному сервису, поиск города — геокодеру; это объяснено пользователю.

## Проверка и границы

Офлайн Kotlin-проверки ядра, матрица крайних/пограничных сценариев, инварианты, часы/кэш, ошибки данных. Android unit / UI-тесты и CI clean build, lint, debug APK. Реальный запуск только на доступном emulator/device. Не подменять отсутствующий SDK зелёной проверкой ядра. Нельзя называть релиз завершённым без сборки и запуска.
