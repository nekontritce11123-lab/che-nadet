# Чё надеть?

Android-приложение, которое отвечает на три вопроса: что сейчас на улице, как это ощущается и какую одежду выбрать. Рекомендации — локальные детерминированные правила, без LLM, нейросетей, аккаунтов, рекламы и API-ключей.

## Что реализовано в коде

Главный экран: город, фактическая и ощущаемая температура, короткое описание, одежда слоями, обувь, полезные вещи, предупреждения, причины и интерактивные показатели. Есть почасовой прогноз на горизонт выбранной активности. Состояния loading/empty/offline/stale/expired отделены от нормального экрана.

Город определяется однократным foreground-запросом примерного местоположения или выбирается поиском вручную. Не требуется фоновое разрешение. Отказ в разрешении не закрывает ручной выбор. При смене города старые данные не показываются под новым названием; запоздавшие ответы отбрасываются.

Персонализация: «постоянно мёрзну / обычно / часто жарко» и четыре режима активности. Изменения сразу пересчитывают одежду, но не подменяют метеорологическую ощущаемую температуру на экране. Настройки и последний ответ API сохраняются локально.

Светлая/тёмная тема, тёплый или холодный акцент, простая векторная иллюстрация, прокручиваемые объяснения, увеличенные области нажатия. При большом системном шрифте показатели перестраиваются в один столбец. Фактическая проверка на устройстве и с TalkBack ещё нужна.

Вход ядра: `WeatherConditions + UserProfile`. Выход: структурированные состояние, слои, аксессуары, предупреждения и причины. Ядро не импортирует Android, Compose, сетевые библиотеки или JSON. Russian presentation вынесен из правил.

## Как принимается решение

1. Данные проверяются по диапазонам и единицам. Отсутствующий показатель остаётся неизвестным, а не нулём. Время — `Instant`, часовой пояс используется только при отображении.
2. При наличии используется `apparent_temperature` провайдера. Ветер и влажность не вычитаются из неё ещё раз. Без этого поля доступны ограниченные по области применимости wind chill и heat index; иначе честно используется температура воздуха.
3. Чувствительность ±2°C и поправка активности меняют только выбор одежды. Непрерывный показатель потребности в тепле и съёмные/необязательные слои сглаживают переходы. Это не устраняет все дискретные границы предметов одежды.
4. Ветер, дождь и снег независимо добавляют защиту. Вероятность осадков не означает, что сейчас идёт дождь. Дождевик может дополнять тёплую куртку, а не заменять её в мороз.
5. На горизонте 1/3/6 часов учитываются похолодание, осадки, ветер, UV и опасные условия. Зонт не советуется при сильном ветре/грозе или недостаточной информации о ветре; вместо него — подходящая защита и предупреждение.
6. Опасности имеют приоритет над обычным советом; профиль не выключает предупреждения. Ледяные условия оцениваются по фактической температуре и осадкам, а не только по wind chill.

Проверяются жара, мороз, насыщенная влажность, ветер/порывы, дождь разной интенсивности, снег, гроза, ледяные осадки, высокий UV, ночь, большая разница фактической/ощущаемой температуры и изменение условий. Есть проверки сочетаний, null/NaN/ошибочных значений, крайних входов и времени кэша.

**Пороги одежды, поправки профиля и сроки свежести — продуктовые эвристики, не клинически валидированная модель терморегуляции.** Тесты доказывают заданные свойства и непротиворечивость в проверенных сценариях, а не универсальную комфортность любой одежды.

## API, лицензия и приватность

Используется Open-Meteo Forecast + Geocoding API без ключа. Бесплатный endpoint предназначен для **некоммерческого** использования. Перед монетизацией/рекламой нужно пересмотреть условия сервиса. Данные требуют атрибуции CC BY 4.0; Open-Meteo и GeoNames указаны в приложении. MIT относится к нашему коду, не меняет лицензию погодных данных. Нет SLA и официального канала штормовых оповещений.

Текущие осадки нормализуются из накопления за `current.interval` в интенсивность за час; прогнозные осадки уже относятся к часовому интервалу. Вероятность осадков заканчивается на конкретной часовой границе. Старый кэш не продлевает её «в будущее». Фактическое время получения и модельное время условий хранятся отдельно от времени оценки.

Координаты округляются до 0,01° перед запросом погоды и обратным геокодированием. Это не анонимизация: сервис получает координаты и IP. Поиск передаёт текст города Open-Meteo; системный Geocoder может использовать сервис поставщика Android. Приложение само не имеет аналитики, не пишет координаты в логи и не использует LLM. В системе сохраняются последний город, профиль и один ответ API. Облачный backup отключён. Удалить данные можно через настройки Android → приложения → Чё надеть? → хранилище.

Автообновление при foreground ограничено свежестью; кнопка позволяет обновить явно. Ответ не больше 1 MiB; connect timeout 8 секунд, read timeout 10 секунд, HTTPS only, redirects запрещены. Это тайм-ауты операций, не строгий общий deadline HTTP-запроса.

## Запуск и сборка

Нужны JDK 17, Android SDK Platform 36 / Build Tools 35.0.0, сеть для Gradle/Maven. Рекомендуется открыть корень проекта в Android Studio и указать SDK. Либо задать `ANDROID_HOME` / `sdk.dir` в некоммитимом `local.properties`.

```bash
# Из Git-истории обязательно выбрать полный Android-кандидат:
git switch development/android-v1

# Linux / macOS с Bash 4+ / Git Bash:
./gradlew --no-daemon clean :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
# С запущенным эмулятором или устройством:
./gradlew --no-daemon :app:connectedDebugAndroidTest
```

Windows PowerShell: `./gradlew.bat --no-daemon :app:assembleDebug`. Bootstrap для Windows создан, но не выполнялся в этой среде.

**Важно о wrapper:** бинарный `gradle-wrapper.jar` не добавлялся. `gradlew` / `.bat` здесь — прозрачный source-only bootstrap: скачивает фиксированный Gradle 8.13, сверяет SHA-256 из официального списка и запускает его. Это не стандартный Gradle Wrapper. При уже установленном Gradle 8.13 можно выполнять те же команды через `gradle`. После нативной проверки рекомендуется сгенерировать и проверить стандартный Wrapper; эту непроверенную подмену автоматически не выполняем.

После успешной сборки ожидаемый APK: `app/build/outputs/apk/debug/app-debug.apk`. Наличие этого пути в документации **не означает**, что APK уже создан. Release signing не настроен, Play-публикации нет.

## Восстановление истории из поставки

Архив исходников содержит полный Android-кандидат без `.git`, SDK, build outputs или секретов. Отдельный `che-nadet-history.bundle` сохраняет Git-историю и ветки:

```bash
git clone che-nadet-history.bundle che-nadet
git -C che-nadet switch development/android-v1
```

Для публикации подготовлен `scripts/publish-github.sh`: он требует чистый Git checkout, SDK, подключённое устройство/эмулятор и GitHub CLI. Сначала выполняет сборку, lint, unit и UI tests; лишь при успехе создаёт новый публичный `che-nadet` и отправляет текущую проверенную версию в remote `main`. Существующие репозитории не перезаписывает. Скрипт не запускался с реальным GitHub; его наличие не считается публикацией.

## Известные ограничения и следующий необходимый шаг

Нативная компиляция, APK-install/launch, реальная геолокация, системный permission flow, live HTTP и визуальная проверка не выполнены. До этих проверок нельзя называть приложение полностью рабочим. Основной следующий шаг — восстановить checkout на машине с Android SDK, выполнить весь verification gate и только затем публиковать main.

Нет офлайн-базы городов: первое открытие и новый поиск требуют сеть. Нет фонового трекинга/уведомлений. Название местоположения может быть общим, если системный геокодер недоступен. Только русский интерфейс, Android 8.0+, системная тема; pull-to-refresh не добавлен, есть явная кнопка.

Нет гарантий точности на конкретной улице, нет медицинской персонализации, собственной карты гроз/оповещений, физиологической калибровки или многодневного планировщика. Туман и мокрый снег не имеют отдельных развитых текстовых состояний; часть нераспознанных кодов отображается без ложного утверждения о ясном небе. Быстрое обычное потепление не имеет отдельной модели смены гардероба; вечернее похолодание и будущие опасности учитываются.

Саморевью автора не заменяет независимое code review. Реальные пользовательские испытания порогов одежды, стандартный Gradle Wrapper и доработка accessibility после device-тестов — более разумные следующие улучшения, чем расширение числа экранов.
